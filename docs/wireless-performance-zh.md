# 无线性能保护

在2023款唐DM-i冠军版、21控制器上，我希望连接期间尽量避免 Wi-Fi 省电带来的短时延迟。这次增加可选的会话性能请求，不修改热点、密码、扫描、选网或配对逻辑。 自用版已在 2023 唐 DM-i 冠军版、平台 21 验证；公共移植分支尚待实测报告。

在“高级”中开启“无线性能保护（实验性）”，下次连接生效。默认关闭，已有用户行为不变。只对无线 CarPlay 有效：会话激活时请求 HIGH_PERF，Android 10 起同时请求 LOW_LATENCY；会话结束或控制器关闭时释放。锁不可用或权限被车机拒绝时继续原连接流程。

新增的 `android.permission.WAKE_LOCK` 是 Android `WifiManager.WifiLock` 的使用要求，所有安装包都会声明这一权限；只有开启本项后的无线会话才会请求 Wi-Fi 锁，本项没有创建 CPU 唤醒锁。会话结束、控制器关闭时释放，开启期间可能增加无线模块耗电。[Android 官方说明](https://developer.android.com/reference/android/net/wifi/WifiManager.WifiLock)明确要求使用 Wi-Fi 锁的应用在清单声明该权限。

这是 Android 性能提示，不能保证车机固件采纳，也不承诺降低具体毫秒数。自动化测试覆盖 API 分支、重复获取和释放、单模式失败及释放异常。未在该车机进行本次修改的实车验证，也没有开启前后的报告 `maxGap` 对比，不能据此认定延迟或卡顿已经改善。

实车验证仍待补充：相同车机固件、手机、路线和播放内容，分别关闭和开启本项，保留两次诊断报告，比较视频 `maxGap`、连接时长及通话/导航表现。公共移植分支尚未执行这一步。

本次主线移植已通过仓库要求的完整检查：3029项单元测试，0失败、1项既有跳过；三个应用的静态检查和调试构建通过，公共树及差异检查通过。

公开 GitHub 检查曾在 SettingsBackupServerTest 的端口稳定性测试失败；维护者确认是既有端口冲突，与此项无关。本地完整检查结果和该公开失败记录分别保留，不把本地通过写成公开检查已通过。
